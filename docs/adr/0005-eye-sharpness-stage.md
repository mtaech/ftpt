# 0005 — 识别管线第四阶段：鸟眼锐度评分（eye.onnx）

## 状态

已接受

## 背景

筛选（culling）场景下，"鸟眼是否对焦清晰"是人工挑片的核心判据，目前只能靠肉眼逐张放大检查。已获得 eye.onnx 眼检测模型（~20MB，YOLO 系），需决定：它在管线中的位置、锐度如何量化、结果以什么形态落库、失败语义如何与既有三态共存。

## 决策

**管线位置**：识别管线追加第四阶段——**检测 → 分类 → 名录映射 → 鸟眼锐度**。在检测框（鸟体 BBox，可外扩）裁剪内运行 eye.onnx 二次检测，不做全图并行检测：眼睛是小目标，裁剪后等效分辨率更高，且天然与"这只鸟"绑定，省去眼框归属匹配。第四阶段为**默认阶段**，不提供开关、不做按需动作（避免"已识别无锐度"中间态，遵守不加假想配置项原则）。

**多眼归约**：鸟框内多个眼候选时，只取**最高置信度的单个眼框**评分。正脸双眼同焦平面，评一个足够，成本固定为一次评分。

**锐度量化**：多指标（拉普拉斯方差、梯度幅值、边缘密度等）经 **log 变换压缩量纲后加权线性融合**，产出连续分。权重/偏移在人工标注"锐利/模糊"的样片集上标定。分数**只保证单调性**，不追求绝对刻度。

**分数形态与持久化**：连续分落库，"锐利/模糊"阈值后置到 UI 消费时应用。recognition 真相表加两列：`eye_sharpness REAL NULL` + `eye_bbox TEXT NULL`（文本格式 `"x1,y1,x2,y2"`，复用 BBox::to_db_string/parse，与既有 bbox 列同格式；**归一化坐标相对全图**，与检测框同坐标系），rusqlite_migration 加一版迁移。生命周期与识别结果一致，删除/复制/重命名随文件走的既有同步逻辑自动覆盖。眼框落库使预览可叠加显示评分依据。

**失败语义**：RecognitionStatus 三态**不变**。无鸟 / 有鸟无眼 / 评分失败统一为 NULL，Confirmed 只断言鸟种管线成功，不被锐度绑架。

**本期范围**：管线第四阶段 + recognition 表迁移 + 信息面板展示分数。筛选交互（阈值滑杆、"仅显示眼锐利"）留待阈值标定后另行实现。

## 被否决的选项

| 选项 | 否决原因 |
|---|---|
| 全图并行跑 eye.onnx | 小目标漏检风险高；需额外的眼框→鸟归属匹配逻辑 |
| 以眼代鸟（弃 detect.onnx） | 颠覆已验证的两段式；找不到眼≠没有鸟 |
| 锐度由 eye.onnx 模型头直接输出 | 模型能力未确认，需先 dump 输出张量验证；不可控 |
| 二值判定落库 | 阈值标定错误需全量重跑；违背阈值后置 |
| 分数+判定双列 | 冗余列不一致时语义模糊 |
| 独立按需触发 | 产生"已识别无锐度"中间态，筛选语义含糊 |
| AppConfig 加开关 | 无真实第二需求，ADR 0003 已否决假想配置项 |
| 新增第四状态 ConfirmedNoFocus | 三态膨胀为四态，所有消费方都要改，换来的区分度可用 NULL 表达 |
| 眼阶段失败降级 NeedsReview | 锐度绑架鸟种状态 |
| 眼框不落库 | 预览高亮需重跑模型；一列文本成本极低 |
| 眼框进缓存表 | 重算要跑模型，不是廉价缓存，语义错误 |
| 分位数归一融合 | 分数依赖同批样本分布，换批不可比，与阈值后置冲突 |

## 影响

- 正：所有 Confirmed 行都有分数（或语义明确的 NULL），筛选/排序可直接消费
- 正：三态语义不动，UI、筛选、测试零改动兼容
- 正：眼框落库支撑"这分评的是不是真眼睛"的人工复核
- 负：识别耗时增加一次推理（眼检测 + 评分）；不想要锐度的用户无开关
- 负：融合权重需在真实样片集上标定，初版分数只有单调性保证
- 负：发布体积 +20MB（models/eye.onnx 随包分发，package.ps1 同步）
