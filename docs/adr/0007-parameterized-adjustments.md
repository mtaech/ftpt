# 0007 — 参数化非破坏调整（右侧「调整」tab）

## 状态

已接受

## 背景

culling 工作流中「这张 RAW 曝光能不能救」是高频判断，目前应用内无法验证——只能切到外部工具。需求：右侧信息面板新增「调整」tab，提供最基础的 RAW 调整（曝光等）。约束排序：**性能指标放在第一位**，功能完整性次之——调整是逐帧连续交互（slider 拖动、画布拖拽），任何一档性能退化都会直接毁掉体验。

## 决策

### 模型：参数化非破坏

调整 = 对一个 Capture 的可逆参数化修改集合。**母版文件永不修改**——调整以参数形式持久化，预览时实时应用，导出时才烘焙到像素（导出功能当前未接线，参数先入库，等导出出现时直接读取）。v1 四类参数：

| 参数 | 作用域 | 标度 | 范围 |
|---|---|---|---|
| 曝光（Exposure） | 像素值变换 | EV | ±2.0，步进 0.05（+1.0 EV = 曝光量翻倍） |
| 对比度（Contrast） | 像素值变换 | 百分比 | -100 ~ +100，0 中性 |
| 饱和度（Saturation） | 像素值变换 | 百分比 | -100 ~ +100，0 中性（-100 = 去饱和） |
| 裁切（Crop） | 几何变换 | 归一化矩形 [x1,y1,x2,y2]（0–1） | 全图 = 无裁切 |

- **per-capture**：每张图独立参数，folder_db 新增 `adjustments` 表，键 = 主显示文件相对文件夹根路径（与 recognition 表同模式），删除/移动/复制/重命名时随文件走的既有同步逻辑扩展覆盖
- **全零参数 = 无调整**（无调整记录即原图，与「从未识别」同构）
- **全格式统一**：RAW 与 JPEG 同一参数模型、同一应用逻辑，不做格式分支（JPEG 直出同样需要曝光评估）
- **应用顺序**：先裁切（几何）→ 再色调调整（像素）→ 最后缩放显示
- 术语已入 CONTEXT.md（调整 / 曝光 / 对比度 / 饱和度 / 裁切 / 裁切框，裁切框与 BBox 语义区分）

### 渲染链路：显示分辨率变换 + 16-bit 母版

- **无调整（参数全零）→ 短路到现有路径，零回归**：现有 8-bit 预览/全分辨率链路完全不变
- **JPEG 有调整**：现有 8-bit 源 → 显示分辨率 tone 变换 → RenderImage（JPEG 直出即 8-bit，无高位信息，不需升级）
- **RAW 有调整**：像素源从「内嵌预览/half_size 8-bit」升级为 **half_size + 16-bit** 解码（`rawlib::DecodeOptions` 新增变体：half_size + output_bps=16 + 自动亮度 + sRGB + 相机白平衡）。16-bit 解码结果作为**母版缓冲**缓存（不落磁盘或落磁盘另议），**参数变更只重算像素变换，不重复解码**——slider 拖动的实时性依赖此点
- **显示链路恒为 1600px**：16-bit 母版先缩到 1600px（保留 16-bit 精度）→ tone 变换 → 降 8-bit BGRA RenderImage。slider 拖动时只走此链路
- **全分辨率链路（1:1 / 放大）**：slider 拖动中用 1600px 链路即时反馈；全分辨率重算在 slider 释放后异步进行（避免拖动中 30-100ms 掉帧）
- **色调变换实现**：曝光（乘法）+ 对比度（围绕中灰缩放）+ 饱和度（RGB→亮度加权混合）在同一次像素遍历内完成
- **裁切 UI**：预览叠加层（复用现有检测框叠加机制）画布框选 + 拖拽手柄（边/角可调）+ 光标反馈；Shift+drag 交互与识别框选同构
- **调整视图（Adjustment View）**：进入「调整」tab 时预览为干净取景上下文——**强制隐藏全部识别叠加层**（检测框、鸟眼角标、pending 识别框），仅显示裁切框。实现为**渲染层条件判断**（`active_tab != Adjust && bbox_visible`），不修改 `bbox_visible` 状态：切回「信息」tab 自动恢复原显示状态，v 键在调整 tab 下按了只改状态不显示，零恢复逻辑、零竞态

### 持久化

folder_db 新表 `adjustments`（rusqlite_migration 加一版）：键 = 相对路径，列 = `exposure REAL`、`contrast INTEGER`、`saturation INTEGER`、`crop TEXT NULL`（`"x1,y1,x2,y2"` 文本，复用 BBox 序列化格式）。upsert/get/delete 与 recognition 表同构，sync_delete/copy/rename 扩展覆盖。

### 导出（v1：单张烘焙）

v1 提供单张导出闭环——**裁切的价值依赖导出兑现**（无导出时裁切框只是预览叠加，输出区域永远不产生真实结果）。焦点图 → 烘焙（先裁切 → 再色调调整）→ JPEG 输出。

- 入口：调整 tab 底部「导出」按钮（焦点图）
- 目录：rfd 目录选择对话框
- 命名：`{stem}_adjusted.jpg`，目标已存在自动追加序号（不覆盖原文件）
- 格式/质量：JPEG 95
- 分辨率：全尺寸——RAW 走全尺寸 16-bit 解码（`DecodeOptions::quality()`：AHD + 16bit），JPEG 原分辨率
- 异步：worker 批量池 + 状态栏进度，不占交互池、不影响 slider 实时性
- 导出是调整管线的延伸：16-bit 源 + tone + crop 复用同一实现，仅增加编码与写盘

### v1 范围

预览 + 持久化 + 重置 + **单张导出**。批量导出、筛选「已调整」、JPEG 高位源、格式选择（TIFF/PNG）留待后续。

## 性能预算（第一约束，每条可验证）

| 指标 | 预算 | 实现保证 | 验证 |
|---|---|---|---|
| slider 拖动帧率 | ≥ 60fps（1600px tone 变换 ≤ 5ms/帧） | 显示链路恒 1600px；变换单次遍历；**主线程零像素工作** | 拖动时主线程无计算，worker 重算 |
| 切图后调整预览首帧 | = 现有预览加载时间（零回归） | 8-bit 预览立即显示，16-bit 升级异步就绪后无缝替换 | 对比调整功能接入前后的切图耗时 |
| RAW 16-bit 母版首次就绪 | ≤ 2s（half_size+16bit，后台） | 走 `worker.spawn_fast`（交互优先池）；不阻塞显示 | 计时 + 视觉确认无等待白屏 |
| 参数变更重算 | 不触发重新解码 | 16-bit 母版缓冲复用；仅重算像素变换 | slider 全程拖动，CPU 无解码峰值 |
| 16-bit 母版内存 | ≤ 40MB/张（6MP×3×2B），只保留焦点图 | 复用 FULLRES 缓存淘汰语义（FULLRES_CACHE_LIMIT=2） | 连续切图，内存无累积 |
| slider 快速拖动 | 旧重算任务可取消/丢弃 | AtomicBool 合作式取消 + 参数版本号（只认最新），复用 preview_cancel 模式 | 快速来回拖动，任务无堆积、画面无滞后回跳 |
| 切图竞态 | 过期渲染结果丢弃 | 复用 scan_generation 换代机制 | 快速切图，无张冠李戴 |
| 无调整图 | 现有路径零改动 | 参数全零短路 | 回归测试 |
| 导出任务 | 异步执行不阻塞交互（全尺寸 16-bit 解码 3-5s） | worker 批量池 + 状态栏进度 | 导出进行中 slider 拖动仍实时 |

**性能机制全部复用现有基建**：双池 worker（批量池 + 4 线程 fast 池）、`spawn_fast` 交互优先、AtomicBool 合作式取消、`scan_generation` 换代丢弃、磁盘缩略图缓存。调整功能不引入新机制。

## 被否决的选项

| 选项 | 否决原因 |
|---|---|
| 纯临时调整（不持久化） | 调完即丢无留存价值；culling 决策记录是真实价值 |
| 破坏性写回/立即导出 | 缺中间态无法反复微调；导出功能当前不存在（convert 未接线） |
| 仅 RAW | 预览链路全格式统一，加格式分支反而费事；JPEG 同样需要曝光评估 |
| 仅曝光单参数 | 曝光拉完中间调发灰几乎必配对比度；三件套同一次遍历实现成本相同 |
| 全局一套参数 | 与 folder_db per-capture 模式不同构；culling 逐张评估场景无意义 |
| 8-bit 上做调整 | 大范围曝光条带化 + **误判风险**（8-bit 拉不出暗部细节会误判 RAW 报废）；16-bit 是 RAW 曝光调整底线 |
| 全尺寸 16-bit | 3-5s 解码 + 单张 ~144MB 缓冲，slider 交互不可用 |
| GPU shader | 8-bit 输入上限救不了输入量化；GPUI shader 复杂度/调试成本高（AGENTS.md 已有 GPUI 静默失败警告）；全 CPU 管线与项目现状一致 |
| 防抖 / 松开才更新 | 连续反馈操作延迟感知强，违背所见即所得 |
| v1 含批量导出 | 批量导出交互（全量进度/取消/命名规则/格式多选）是独立完整 feature，v1 撑大 2-3 倍；单张导出已闭环裁切价值，批量后补 |
| 裁切数值输入 | 裁切是视觉操作，填数字违背直觉 |
| 归一化 / 百分比标度 | slider 上的 0.37 对摄影师无意义；EV 是摄影通用语言 |
| 裁切一次性框选（无手柄） | 框选很难一次到位，裁切微调是高频操作；手柄是纯叠加层增量 |
| 状态快照/恢复隐藏叠加层 | 异常路径/竞态下状态泄漏；渲染层条件判断零恢复逻辑 |

## 修订（2026-08-01：裁切功能移除）

裁切（含裁切框、框选/手柄交互、叠加层、导出裁剪、crop 参数）已按用户要求整体移除：

- `AdjustParams` 删 `crop` 字段；`apply_crop16/8`、裁切交互（`adjust_mouse_down/move/up`）、裁切叠加层、导出裁剪全部删除
- preview 鼠标事件恢复原逻辑（Shift+拖拽 = 识别框选，普通拖拽 = 平移）；调整视图语义保留（隐藏识别叠加 + 调整渲染优先）
- folder_db `adjustments` 表保留，但 `crop` 列不再读写（已迁移库兼容，列置 NULL）
- 术语表删「裁切 / 裁切框」；曝光 / 对比度 / 饱和度 slider 与导出保留

移除原因：裁切交互（画布框选 + 手柄微调）在目标锁定 gpui 4ebc154 环境下实测不可用，用户选择放弃该子功能而非继续调试。

## 影响

- 正：culling 决策闭环（拉曝光 → 看效果 → 参数入库 → 切下一张），RAW「能不能救」可验证
- 正：RAW 有调整时预览精度整体升级（16-bit），无调整零回归
- 正：参数先入库，导出功能出现时直接读取，无迁移
- 负：RAW 有调整时首次预览多一次 16-bit 解码等待（≤2s，后台不阻塞）
- 负：单张导出全尺寸 RAW 解码 3-5s（异步，状态栏进度，不可取消）
- 负：16-bit 母版内存占用（≤40MB 焦点图，受淘汰策略约束）
- 负：folder_db 加一表 + sync 同步逻辑扩展（与 recognition 同构，成本可控）
- 负：裁切手柄实现量（命中检测/手柄渲染/光标反馈）高于一次性框选
