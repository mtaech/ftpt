# 0006 — 批量文件操作重构：筛选驱动 + 画面粒度

## 状态

已接受

## 背景

批量文件操作（文件操作 tab）原为**独立功能**：源目录 vs 对比目录的格式匹配引擎（`find_matching`：Copy/Delete/Move × 同名/非同名 6 种操作），目标目录写死为对比目录父目录的 `batch_output`。它与主工作流割裂——用户实际流程是"浏览 → P/X 标记 → 筛选 → 对筛选结果执行操作"，批量操作却要求额外维护"对比目录 + 源/对比格式"两套概念。

同时，架构决策"每文件一个 Capture、JPG/RAW 不堆叠配对"导致**"同步操作同名不同后缀文件"的能力缺失**：筛选出 JPG 后想连同同 stem 的 NEF 一起移动/删除，无任何机制支持。用户领域观点：**兄弟文件也是同样的画面**——`IMG_001.JPG` 与 `IMG_001.NEF` 对用户是同一张照片的两种格式，操作粒度天然是"画面"级。

## 决策

**操作对象 = 当前筛选结果（纯筛选驱动）**。批量操作的边界即 `display_order`（筛选栏全部条件过滤后的集合），与网格所见一致；手动选择（`selected`）不参与批量范围，仅用于单张操作与预览跳转。砍掉"对比目录 + 格式匹配"作为操作对象来源的整条语义。

**动作收敛为三种**：移动（到用户指定目录，跨设备 copy+delete 回退）/ 复制（到用户指定目录）/ 删除（回收站）。"同名/非同名"是对比匹配的概念，随匹配引擎一并移除；目标目录在执行时由用户选择（rfd），不再写死 `batch_output`。

**新增按 stem 的兄弟文件匹配（画面粒度）**。操作时提供「同步同名文件」开关（**默认关**），开启后：

- 以操作集内每个文件的 stem 为键，搜索**整个当前目录**（不受筛选条件限制），把同 stem 的兄弟文件并入操作集
- 格式多选栏决定同步哪些格式（从目录实际存在的格式提取，默认全选，可取消个别）
- 兄弟文件**不过筛**：元数据筛选只管触发点（筛选出的文件），配对是文件系统层面的事实
- 删除类同样适用（整组进回收站）

**确认流程分层**：移动/复制选择目标目录即执行（选目录的动作即确认）；删除强制二次确认，确认信息包含同步拉入的数量（"将删除 N 个文件，其中 M 个来自同名同步"），红色警告。

**UI 位置**：仍为左侧边栏「文件操作」tab（改造现有表单：移除对比目录/源格式/对比格式/操作类型 4 项，替换为目标目录选择、同步开关、格式多选栏、移动/复制/删除按钮）。批量标记不并入——右键菜单已具备（作用于选择集）。

## 交互规格（UI 细节定案）

- **按钮布局**：`[移动到…] [复制到…]` 主操作横排一行；下方**独立红色「删除」按钮**（危险操作视觉隔离，不与主操作并排）
- **删除确认**：弹窗 Dialog——文案「将删除 N 个文件，其中 M 个来自同名同步」+ 前若干条清单 + [取消]/[确认删除]（红色）
- **移动/复制一步式**：点按钮 → rfd 选目标目录 → 选完即执行（取消 = 中止）；拒绝「目标 = 源目录」
- **数量反馈**：面板顶部实时显示「操作对象：当前筛选结果（N 张）」；勾选「同步同名文件」后显示「+M 格式」同步预估（筛选/开关变化时惰性计算一次，删除弹窗复用同一份匹配）
- **执行反馈**：状态栏进度条（done/total）+ 完成时 Notification toast 摘要「成功 N / 失败 M」+ 侧栏失败详情列表
- **边界状态**：筛选结果为空 → 三按钮禁用置灰 + 提示；目录无兄弟格式 → 允许勾选但提示「目录中没有其他格式的同名文件」；格式多选全取消 → 无扩展（不强制联动）
- **完成后刷新**：删除/移动执行完 → 触发全量重新扫描（`scan_directory` 复用：folder_db 三表同步、识别行/XMP 清理、网格刷新一次到位），不做局部剔除

## 被否决的选项

| 选项 | 否决原因 |
|---|---|
| 保留对比目录匹配为高级模式 | 两个"操作对象来源"并存（筛选结果 vs 对比匹配）使 UI 与心智模型分裂，与"全局贯通"目标相悖 |
| 手动选择参与批量范围（筛选∩选择） | 筛选与选择语义叠加产生歧义（选中的文件被筛选过滤掉怎么办）；用户流程不需要 |
| 兄弟文件重新过筛 | "只显示 JPG"时 NEF 永远不满足筛选条件，同步功能名存实亡 |
| 同步范围限定 RAW 家族（JPG↔NEF 白名单） | 需维护配对白名单；任意后缀按 stem 分组更简单可预期 |
| 批量标记并入面板 | 右键菜单已支持对选择集批量标记，重复建设 |
| 批量重命名并入 | 需要命名模板/编号规则 UI，语义独立；违背"只做一件事" |
| 工具栏按钮 + 弹窗入口 | 用户选择侧边栏 tab 扩展 |
| 干跑预览列表（全操作） | 操作对象即网格可见的筛选集，预览价值低；删除改为强制确认替代 |
| 完成后局部剔除（不重扫） | 用户选全量重扫：状态一致性优先，folder_db 同步/缩略图重建一次到位，避免局部剔除的残留风险 |

## 已验证项

- 筛选驱动：`apply_filter_and_sort` 已产出 `display_order`，网格渲染即消费该集合，无额外机制成本
- 兄弟文件匹配：`CaptureMeta.base_name` 即 stem（不含扩展名），`captures` 持有完整目录清单，可按 stem 分组
- 删除已走回收站（`ops::delete_capture` → `trash::delete`），非永久删除
- 跨设备移动回退（copy+delete）与识别行/XMP 同步已在 ops 层就绪

## 影响

- `photo-domain`：`BatchOpType` 枚举重构——移除 Same/NotSame 六个变体，替换为 Move/Copy/Delete 三动作（`is_same_match`/`needs_target_dir`/`description`/`is_delete` 随之调整）
- `photo-engine::batch_ops`：`find_matching` 删除；`execute` 重写为"对 capture 索引列表 + 目标目录直接执行"；新增兄弟文件匹配（按 stem 分组、格式过滤）
- `photo-tool-app`：状态字段清理（`batch_compare_dir`/`batch_source_format`/`batch_compare_format`/`batch_op_type` 等删除，新增 `batch_sync_enabled`/`batch_sync_formats`）；`batch_ops.rs` UI 重写
- CONTEXT.md：新增"画面（Shot）"/"兄弟文件"术语，移除死术语 DeleteMode
- 不做：撤销/undo（记录为已知限制，v2 候选）
